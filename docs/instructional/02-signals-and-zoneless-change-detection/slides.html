Coursewright frontend · Lesson 02

Signals and Zoneless
Change Detection

What makes the screen update when there's no zone.js, and where state should live: a signal, a resource, a service or a store.

The questions this lesson answers

  • How do signals change change detection in a zoneless app?
  • When is an effect the wrong tool?
  • When would you not use a store?
  • Why is the search box a linkedSignal, not a computed?
  • When would you use httpResource rather than an RxJS pipeline?
The thesis

Without zone.js, Angular renders only when it's told. A signal is the most precise way to tell it.

It says what changed, and which views read it.

What zone.js used to do

1Patch timers, promises, events, XHR
2A callback finishes
3The zone tells Angular
4Check the whole tree, root down

It had no idea what changed, so it checked everything.

Convenient, and expensive

Worked by accident

Assign a plain field in a subscribe callback, and the zone noticed.

The costs

  • A whole-tree check after every async task
  • Patched browser APIs
  • One more library in every bundle

Two building blocks

signal()

Holds a value you set. Readers are notified when it changes.

computed()

Derived from other signals. Lazy, memoized, glitch-free. Read-only.

Glitch-free: never computed from one new input and one old one.

The search box needs two things

Local and writable

Every keystroke sets it, before the URL catches up.

Follows the URL

Back button or a shared link: the box must show ?q=.

linkedSignal: writable, and resets

apps/web/src/app/features/catalog/catalog-page.ts · excerpt

/** The search box's value: local, seeded from the URL, and reset whenever the URL changes. */
protected readonly query = linkedSignal(() => this.q() ?? '');
// …

  this.query.set(value);
  // …
}

Follows the URL, but read-only.

httpResource: a read as signals

apps/web/src/app/core/api/coursewright-api.ts · excerpt
/** A signal-driven GET that refetches when `courseId` changes. Call it from an injection context. */
course(courseId: () => string): HttpResourceRef<Course | undefined> {
  return httpResource<Course>(() => `/api/courses/${encodeURIComponent(courseId())}`);
}

Takes a function, not a string: the URL re-derives when the ID signal changes.

The heading is derived state

apps/web/src/app/features/course/course-page.ts · excerpt
// One h1 whose text changes, rather than one h1 per state: route focus lands on it while
// the course is still loading, and replacing the element would drop that focus.
protected readonly heading = computed(() => {
  if (this.course.hasValue()) return this.course.value().title;
  if (this.notFound()) return 'Course not found';
  if (this.course.error()) return 'Course unavailable';
  return 'Loading course…';
});

Resources are for reads

Resource

GET a course, list enrollments. Re-runs when its inputs change.

Not for a POST

Enrolling must not run twice. It's an RxJS pipeline: lesson 03.

Effects

An effect pushes signal state into something that isn't a signal.

It runs asynchronously, during change detection, not when the signal is set.

Effect 1: the document title

apps/web/src/app/features/course/course-page.ts · excerpt
constructor() {
  // The route's title is only "Course"; once loaded, the browser tab names the course.
  effect(() => {
    if (this.course.hasValue()) {
      this.title.setTitle(`${this.course.value().title} · Coursewright`);
    }
  });
  // …
}

document.title isn't a signal, so an effect is the bridge.

When not to use a store

docs/adr/0004-signals-and-rxjs-state.md · Consequences, Negative

@ngrx/signals is a dependency; plain services with signals would do for an app this size. It's here because it's the pattern a team of this size standardizes on.

The rule

Start with a signal where the state is used. Promote it when a second consumer needs it, or the coordination grows.

Zoneless isn't free

  • Plain fields assigned in callbacks silently stop updating
  • Some third-party libraries still assume a zone
  • Tests await fixture.whenStable() (lesson 10)
  • Two reactive models: "state, or an event?" is a review question

What production would add

  • Entity collections (withEntities)
  • Optimistic updates with rollback
  • Cross-tab sync (BroadcastChannel)
  • Store devtools

Traps

  • A plain field assigned in a subscribe or a timer, expected to render
  • A signal's value copied into a field once
  • An effect that derives state, or copies one signal into another
  • An array or object mutated inside a signal
  • A resource outside an injection context, or for a POST
  • A store by default
Interview drill

Five questions

After each question, pause and answer out loud. Then compare with the model answer.

Question 1 of 5

How do signals change change detection in a zoneless app, and what still triggers a render?

Answer out loud.

Model answer
  • No whole-tree check after every async task
  • Triggers: template signals, listeners, markForCheck, setInput, attach/remove
  • Timers, promises, plain-field assignments: nothing
  • Only views that read the signal refresh; OnPush ancestors are walked past
Question 2 of 5

When is an effect the wrong tool, and what would you use instead?

Answer out loud.

Model answer
  • When the result is state
  • computed: read-only derived (statusText)
  • linkedSignal: writable, resets from a source (the search box)
  • Resources for reads; handlers or RxJS for events
  • Effect: sync to a non-signal (title, focus)
Question 3 of 5

When would you not use a store, and just keep a signal in the component?

Answer out loud.

Model answer
  • One component's state: signals there (login page)
  • A read keyed by state: a resource (course page)
  • A small workflow: an injectable with signals (enrollment)
  • A store when fields and async flows coordinate (catalog)
Question 4 of 5

Why is the search box a linked signal and not a computed?

Answer out loud.

Model answer
  • Writable: every keystroke sets it; computed is read-only
  • Resets when ?q= changes from outside
  • linkedSignal: writable and re-derives from its source
  • Signal + effect copying the input: extra pass, hidden dependency
Question 5 of 5

When would you load data with httpResource rather than an RxJS pipeline?

Answer out loud.

Model answer
  • httpResource for a read keyed by state (the course)
  • Value, error, loading, status code as signals
  • RxJS when timing matters: debounce, cancel, ignore, append, retry
  • Never a resource for a write
