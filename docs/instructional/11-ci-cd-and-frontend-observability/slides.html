A W3C traceparent header

Added by the web app's trace interceptor to every /api/ request.

The trace interceptor

apps/web/src/app/core/observability/trace.interceptor.ts · excerpt
export function createTraceparent(traceId = createTraceId()): string {
  return `00-${traceId}-${randomHex(8)}-01`;
}
// …
// Every call gets its own trace, which the BFF continues and returns in problem+json `traceId`,
// so a user-reported error leads straight to the server logs for that request.
export const traceInterceptor: HttpInterceptorFn = (request, next) =>
  request.url.startsWith('/api/')
    ? next(request.clone({ setHeaders: { traceparent: createTraceparent() } }))
    : next(request);

The random bytes come from crypto.getRandomValues.

Tracing runs before auth

apps/web/src/app/app.config.ts · excerpt
export const appConfig: ApplicationConfig = {

    provideHttpClient(withInterceptors([traceInterceptor, authInterceptor])),

Two response headers close the loop

apps/bff/src/observability.ts · condensed
export function registerObservability(app: FastifyInstance): void {
  // …
  app.addHook('onRequest', async (request, reply) => {
    request.startTime = performance.now();
    // Same trace, new span id: this server's work is a child of the caller's span.
    reply.header('traceparent', `00-${request.id}-${randomBytes(8).toString('hex')}-01`);
  });
  app.addHook('onSend', async (request, reply) => {
    // Browsers show Server-Timing in DevTools and expose it to RUM via PerformanceResourceTiming.
    const duration = performance.now() - request.startTime;
    reply.header('server-timing', `app;dur=${duration.toFixed(1)}`);
  });
}

The test pins it down

apps/bff/test/observability.test.ts · excerpt
it('continues the caller trace with a new span, and puts its id in problems', async () => {
  const response = await app.inject({
    url: '/api/me/enrollments',
    headers: { traceparent: `00-${TRACE_ID}-${PARENT_ID}-01` },
  });

  const [version, traceId, spanId, flags] = String(response.headers['traceparent']).split('-');
  expect([version, traceId, flags]).toEqual(['00', TRACE_ID, '01']);
  expect(spanId).toMatch(/^[0-9a-f]{16}$/);
  expect(spanId).not.toBe(PARENT_ID);
  expect(response.json()).toMatchObject({ status: 401, traceId: TRACE_ID });
});

Also: missing, malformed or all-zero headers start a new trace; Server-Timing on every response.

Batched, and sent when the page is hidden

apps/web/src/app/core/observability/rum.ts · excerpt
start(): void {
  // …
  // "hidden" is the last event a page reliably gets: mobile browsers may discard a background
  // tab without ever firing unload. web-vitals reports its final LCP/INP/CLS values then, too.
  this.document.addEventListener('visibilitychange', () => {
    if (this.document.visibilityState === 'hidden') this.flush();
  });
}
// …
private record(event: RumEvent): void {
  // …
  this.batch.push(event);
  if (this.batch.length >= MAX_BATCH) this.flush();
}

const MAX_BATCH = 10; at the top of the file.

sendBeacon: survives the page going away

apps/web/src/app/core/observability/rum.ts · excerpt
private flush(): void {
  if (this.batch.length === 0) return;
  const body: RumBatch = { events: this.batch };
  this.batch = [];
  // sendBeacon survives the page going away, but can't set headers, so /api/rum is
  // unauthenticated. A string body is sent as text/plain, which the BFF accepts.
  navigator.sendBeacon('/api/rum', JSON.stringify(body));
}

No headers

No bearer token: the endpoint is public.

text/plain

A string body isn't sent as JSON.

Collecting data isn't monitoring

Causes

  • A CPU spike nobody notices
  • A restarted instance

Symptoms users feel

  • Latency percentiles
  • Web vitals

A service level objective

99% of catalog searches render within 1 s.

Error budget

The 1% that may miss, over 30 days.

Measured

From real users, with BFF response time as a second view.

Alert on the burn rate

Fast burn → page

The last hour would spend ~2% of a 30-day budget: a burn rate of ~14×.

Slow burn → ticket

A lower rate, sustained over several hours.

A leading % can't seek: a rare term checks every title the tenant has before LIMIT is met.

What production would add

  • OpenTelemetry web and Node SDKs → a collector that redacts, samples and forwards
  • Same W3C header: new exporters, not a new contract
  • Source maps uploaded, so stack traces are readable
  • A release and a tenant on every RUM event: openapi.yaml first

Traps

  • End-to-end tests before the cheap checks
  • A floating toolchain: unfrozen lockfile, unpinned versions
  • Rebuilding for each environment
  • Deleting the previous release's chunks on deploy
  • Sending RUM on unload
  • A trace ID that never reaches the error the user sees
  • Personal data in RUM: full URLs carry search text
  • Alerting on causes rather than symptoms
Interview drill

Five questions

After each question, pause and answer out loud. Then compare with the model answer.

Question 1 of 5

How do you connect a frontend error to the backend request that caused it?

Answer out loud.

Model answer
  • A traceparent header on every API call
  • The BFF makes the trace ID the request ID: trace_id on every log line
  • Returned in the response header and the problem's traceId
  • The error handler beacons it; one search finds both sides
  • Show a short reference code to the user, for support
Question 2 of 5

CI takes 25 minutes. How do you get it under 10?

Answer out loud.

Model answer
  • Measure the critical path; cheap checks first
  • Cache the store, the build cache, the browsers
  • Parallel jobs; shard E2E; only the journeys that matter
  • Test the built artifact; move low-signal checks after merge
  • With a project graph: affected-only
Question 3 of 5

How do you ship a risky frontend change to 5% of tenants first?

Answer out loud.

Model answer
  • Deploy dark; release by tenant, from the verified token
  • Internal tenant, then 5% of customers
  • Compare cohorts on errors and web vitals
  • Flag off is the rollback; the flag has an owner and expiry
Question 4 of 5

A deploy raised INP p75 by 80 ms. How would you have caught it before 100%?

Answer out loud.

Model answer
  • INP is a field metric: lab tests alone won't catch it
  • Tag every RUM event with the release
  • Small cohort first; compare p75 with the previous release
  • Halt automatically past a threshold, with enough samples
Question 5 of 5

"The catalog has been slow since Tuesday." Walk through your investigation.

Answer out loud.

Model answer
  • Define slow: first load, typing, or results
  • What changed Tuesday: deploy, flag, data
